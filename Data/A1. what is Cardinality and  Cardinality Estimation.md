
## 🔢 What is **Cardinality**?

**Cardinality** means:

> **"How many unique values are in a column?"**

---

### 🔍 Examples:

|`UserId`|`Country`|
|---|---|
|1|Egypt|
|2|Egypt|
|3|France|
|4|France|
|5|USA|

- **Cardinality of `UserId`** = 5 (all values are unique)
    
- **Cardinality of `Country`** = 3 (`Egypt`, `France`, `USA`)
    

---

### 🎯 Types of Cardinality:

|Type|Meaning|Example|
|---|---|---|
|**High**|Many unique values|`Email`, `UserId`, `Phone`|
|**Low**|Few distinct values|`Gender`, `Yes/No`, `Country`|
|**Medium**|Somewhere in between|`City`, `JobTitle`|

---

## 🧠 What is **Cardinality Estimation**?

This is what the **database query planner** does to **guess how many rows** will match a certain condition in your SQL query.

---

### 📦 Why is it important?

When you write:

```sql
SELECT * FROM Users WHERE Country = 'Egypt';
```

The database needs to **guess**:

- "How many rows will match `Country = 'Egypt'`?"
    
- That’s **Cardinality Estimation**.
    

It uses that guess to **choose the best execution plan** (e.g., use an index or not, join method, etc.).

---

### ⚠️ Bad Estimation = Slow Query

If the DB **underestimates**, it might:

- Choose a slow plan (like full table scan)
    
- Cause memory issues or delays
    

---

### 📊 How does it estimate?

- **Statistics** on the data (like histograms)
    
- **Previous query patterns**
    
- **Sampling** from the table
    

---

### 🧪 Example:

Suppose:

```sql
SELECT * FROM Products WHERE Category = 'Electronics';
```

If:

- `Category = 'Electronics'` has **1,000,000 rows**
    
- But the DB **estimates only 10 rows**  
    → It might choose a bad execution plan.
    

---

## ✅ Summary

|Term|Meaning|
|---|---|
|**Cardinality**|Number of unique values in a column|
|**Cardinality Estimation**|Database's guess of how many rows will match a query condition|
